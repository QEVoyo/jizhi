## 一、决策：为什么去掉微信绑定

用户的原话是「个人开发，不是企业，不能直接绑微信」。查下来这句话**对一半**：

| 能力 | 个人主体能不能做 |
|---|---|
| 小程序 `wx.login` 一键登录 | ✅ **能做**，不需要企业资质 |
| 网页/APP 的微信登录（开放平台） | ❌ 要企业主体 + 300/年认证 |
| 公众号网页授权 | ❌ 个人订阅号没有这个接口权限 |
| UnionID 打通小程序↔网页 | ❌ 必须企业 |

**受限的只有网页/APP 那条**，而网页端现在用的是**公众号测试号**兜的
（`auth.py` 的注释里自己写着「请前往 mp.weixin.qq.com/debug 获取测试号」）——
那是开发调试工具，不该上生产。

于是定下：

- **小程序两条登录路径**：① 微信一键登录（**首次由后端直接建号**）② 邮箱/用户名 + 密码
- **不再做「绑定」**：原来的「微信登录 → need_bind → 绑定网页账号或注册」整条删掉
- **公众号测试号扫码整条删除**
- **扫码登录推迟到 Flutter App 出来之后**（用户明确：扫码那一端只做手机应用，小程序不掺和）

### ⚠️ 这里有个洞，以及不用「账号合并」的补法

微信建的号没有邮箱密码 → **用户在网页/桌面/手机端够不着它**，会导致学习数据分裂。

补法**不是**账号合并（那要迁移 user_id，是数据工程），而是**给账号补一把钥匙**：
微信建号后，在设置页可以补真实邮箱 + 密码。补完同一个账号到处都能登。

数据模型也因此定为：占位邮箱 `wx_{openid}@miniapp.local`
（`.local` 是 RFC 6762 保留 TLD，永远不可投递）。

## 二、账号底座（后端 + 小程序）

### 后端 `routers/auth.py`

| 端点 | 变化 |
|---|---|
| `/auth/wx-login` | 查不到 openid 就**直接建号**（原来是返回 `need_bind`）。Admin API 建 auth 用户 + 写 profile |
| `/auth/set-credentials` | 新增。补真实邮箱+密码，复用邮箱验证码。**只对占位邮箱账号开放** |
| `/auth/account-status` | 新增。让客户端知道该显示「修改密码」还是「设置邮箱和密码」 |

**建号那条路做了三层防护**（这个项目在「静默失败」上吃的亏太多了）：

1. profile 写失败 → **回滚删掉刚建的 auth 用户**
   （不回滚的话，每次重试漏一个孤儿账号）
2. **回读校验 openid 真的落库** —— 它是这个账号唯一的找回凭据，
   INSERT 失败会报错但值被改写不会，只有回读能发现
3. 缺 `SUPABASE_SERVICE_ROLE_KEY` 直接 500，**不静默降级**

### 一个小发现：这次改动对旧客户端向后兼容

老版本小程序（已提审那个包）拿到 `need_bind: false` + `access_token` 会直接登录成功。
所以**不会出现「用户更新前完全登不进去」**。

### 小程序

| 文件 | 变化 |
|---|---|
| `pages/login/index.vue` | 383 → 254 行。两条路径，删掉「问是否有账号→绑定→注册」三步 |
| `stores/auth.js` | `login()` 简化，新增 `loginWithPassword` / `fetchAccountStatus` / `setCredentials` |
| `pages/profile/settings.vue` | 「账号安全」按账号状态**二选一** |

**「二选一」不是设计偏好，是必须的**：原来的「修改密码」表单第一步要输**当前密码**，
而微信建号的用户根本不知道那个随机密码——照原样加个入口就是把用户送进一个必然失败的表单。

### ⚠️ 四个坑，每个都值得记

**1. Windows 构建必须先开「开发者模式」**
Flutter 在 Windows 上构建带插件的包需要符号链接支持，没开就只打一行
`Building with plugins requires symlink support.` 然后 1.4 秒退出。
需要管理员权限，我改不了注册表，最后是用户自己开的。

**2. `sdkmanager` 的版本不兼容伪装成了网络问题**
Gradle/AGP 传的包 ID 是分号格式 `ndk;28.2.13676358`，而新版 Android CLI 版 sdkmanager
**不认分号**，会把它拆成两个包名、两个都报 "not found"，然后以 `0xC0000409` 崩溃。
症状看起来像「缺包 / 网络问题」，**实际是格式不兼容，自动安装这条路根本走不通**。
处理：`android.builder.sdkDownload=false` 关掉自动下载，缺什么手动装
（`sdkmanager "ndk/28.2.13676358"`，斜杠格式）。

**3. Gradle 本体下不来**
`services.gradle.org` 307 跳到被墙的 CDN。改 `gradle-wrapper.properties` 到腾讯云镜像，
并把 `-all` 换成 `-bin`（省 100MB，源码文档构建用不上；阿里云没有 gradle 镜像）。

**4. Kotlin 增量编译在这台机器上必挂**
`Could not close incremental caches ... class-fq-name-to-source.tab`。
**删缓存没用**（复现只要 18 秒），是增量编译本身的问题。
`kotlin.incremental=false` 解决。

**另外**：全局 `~/.gradle/init.gradle` 和工程自己的 `allprojects { repositories }` 会打架，
Gradle 9 直接报 `prefer settings repositories over project repositories` 失败。
正确做法是写进工程的两个文件（`settings.gradle.kts` 的 `pluginManagement.repositories`
和 `build.gradle.kts` 的 `allprojects.repositories`），阿里云镜像在前、官方仓库兜底。

2. **后台任务的 exit code 不是被测程序的 exit code。**
   我用 `flutter build apk ... | tail` 起后台任务，收到 `exit code 0` 就报了「构建中」，
   实际 Gradle 早已失败——那 0 是 `tail` 的。**管道会吃掉前面的退出码**，
   之后改成 `cmd > log 2>&1; echo $?`。
3. **「删缓存就好」是个没验证的假设。** 第一次 Kotlin 缓存报错，我判断是「上次构建
   中断留下的坏缓存」。删掉重试——**18 秒原样复现**。真因是增量编译本身不可用。
   **删掉一个东西再复现，和「删了就好了」，是两件事。**
4. **测试写错比代码写错更常见。** 这轮两次失败都是测试自己的问题：
   断言用了 `findsOneWidget` 而页面上本来就该有两个；以及把随机值写死在断言里。
   **测试失败时，先怀疑测试。**
5. **危险的批量删除要先打印「将要删什么」。** 那次误删 helper 就是靠这一步拦下的。
   「先跑试运行、看清单、再写盘」——09-27 已经写进教训，这轮又验证了一次。
6. **一个看起来像网络问题的报错，可能是工具链版本不兼容。**
   `sdkmanager` 报的是 "Package not found"（像缺包/没网），实际是分号格式不被识别。

7. **平台限制 ≠ 产品决策。** 小程序的裁剪（砍视频库、砍编程题）是被平台逼的，
   不是「这个产品不需要」。**用户这一点提醒得很准**：拿小程序当参照会继承它的坑。

### ⚠️ 五个坑，每个都值得记

**1. Windows 构建必须先开「开发者模式」**
Flutter 在 Windows 上构建带插件的包需要符号链接支持，没开就只打一行
`Building with plugins requires symlink support.` 然后 1.4 秒退出。需要管理员权限。

**2. `sdkmanager` 的版本不兼容伪装成了网络问题**
Gradle/AGP 传的包 ID 是分号格式 `ndk;28.2.13676358`，而新版 Android CLI 版
sdkmanager **不认分号**，会拆成两个包名、两个都报 "not found"，然后以
`0xC0000409` 崩溃。**症状看起来像缺包/网络问题，实际是格式不兼容。**
处理：`android.builder.sdkDownload=false` 关自动下载，手动装（斜杠格式）。

**3. Gradle 本体下不来** —— `services.gradle.org` 307 跳到被墙的 CDN。
改 `gradle-wrapper.properties` 到腾讯云镜像，`-all` 换 `-bin`（省 100MB）。

**4. Kotlin 增量编译在这台机器上必挂**
`Could not close incremental caches ...`。**删缓存没用**（复现只要 18 秒），
是增量编译本身的问题。`kotlin.incremental=false` 解决。

**5. 全局 `~/.gradle/init.gradle` 会和工程级配置打架**
Gradle 9 报 `prefer settings repositories over project repositories` 直接失败。
正确做法是写进工程的两个文件（`settings.gradle.kts` 的 `pluginManagement.repositories`
和 `build.gradle.kts` 的 `allprojects.repositories`），阿里云镜像在前、官方仓库兜底。

## 十五、异步任务队列（Redis + arq）

用户：「**最好先架构好这个消息队列，不然后期麻烦一大堆**」。

### 现状勘察

`video_gen.py` **已经有一个进程内队列**（`asyncio.Queue` + `_pending` 去重 +
worker 循环），设计底子是对的（队列只传标识、状态落在数据库行里）。

但有四个洞，正好对应「后期麻烦」：

1. **只在进程内** → 重启全丢
2. **多 worker 不协调** → 起两个 uvicorn = 两套队列，同一格重复跑
3. **没有统一重试/退避** → 每个模块自己实现一遍
4. **前端只能轮询，且会提前放弃** → 视频生成 4 分 14 秒，
   小程序轮询 5×8s=40s 就放弃，**这正是 09-27 查到的「视频一直加载不出来」的根因**

而且 `asyncio.create_task` 已经在四处各写各的。

### 一个重要的取舍：不是所有 create_task 都该迁

| 类型 | 例子 | 处理 |
|---|---|---|
| **用户等着的长任务** | 视频生成、交卷后批量 AI 分析 | **进队列** |
| **藏延迟的优化** | 记忆压缩、智能体 grounding 预取 | **留在原地** |

第二类本来就是「顺手做掉、丢了也无所谓」，挪进队列会从「让响应更快」
变成「延迟执行的副作用」，反而错。

### 落地

```
services/task_queue.py   队列封装 + 任务实现 + 完成通知
worker.py                常驻 worker 入口（带 Redis 预检）
config.py                REDIS_URL + TASK_QUEUE_FALLBACK_INLINE
```

**关键设计：Redis 连不上时默认抛错，不静默降级。**
这个项目在「看起来在跑、其实没跑」上吃的亏太多了（静默吞掉写入失败、
静默 0 行 UPDATE…）。真要退回进程内执行，必须显式打开
`TASK_QUEUE_FALLBACK_INLINE=true`，且日志里会有 ERROR。

**完成通知**：任务跑完写一条进 `notifications` 表（复用已有的 `create_notification`，
它做了聚合 upsert 不会刷屏），用户去消息中心看。不推 SSE/WebSocket。

### ⚠️ 考试那条**没有迁**，理由是它还不满足前提

`exam_papers._batch_ai_analyze_wrong` 是模块私有函数、入参是**内存里的列表**，
而且它在 `_save_paper_record` **之前**触发 —— worker 无从按 ID 重读。
要迁它得先重构：**先存记录、再按 record_id 入队**。
硬塞进来只会做出一个跑不通的任务。

### 验证

- **打桩测试 6/6**：正常入队 / 连不上默认抛错 / 显式开关才退回 / 未知任务当场拒 /
  arq 去重返回 None 不算失败 / 注册表与 worker 函数表一致
- **真·端到端 2/2**（本机 Redis 真在跑，v5.0.14.1）：
  入队 → worker 取走 → 执行 → 结果可查
- **重试在 burst 模式下验不了** —— burst worker 收完就退，而 arq 的重试是
  延迟重排的。生产上 worker 常驻才会发生。**我没有假装验证过它。**

## 十七、版本号与静默更新检查

用户：「桌面端待补：版本号显示 + 启动时静默检查更新」（09-27 留下的待办）。

**分工**：Rust 只暴露版本号，**更新检查放在网页端** —— 网页端已经有 fetch、也知道 API 地址，
加进 Rust 只会多一个 HTTP 依赖和一套重复的错误处理。

| 位置 | 改动 |
|---|---|
| `main.rs` | 新增 `app_version` 命令（网页端不知道壳的版本，只能问壳） |
| `backend/routers/download.py` | `/download/latest` 补 `version` 字段 —— 从文件名 `JIZHI_0.1.0_x64-setup.exe` 解析 |
| `desktop/index.js` | `getAppVersion` / `checkUpdate`（语义化版本比较） |
| `main.js` | 启动 4 秒后静默检查，**只在真有新版时才弹通知** |
| `Settings.vue` | 「关于」加桌面版版本行 + 手动检查更新 |

**「静默」的含义要写清楚**：探测失败（断网、后端没起、安装包还没上传）一律**安静放过** ——

## 十九、设置页左导航 + 固定顶栏 + ⚠️ 内部滚动

用户先要「左侧搞一个导航栏」，然后「返回主界面固定在左上角」，然后
「**怎么右边又有滑轮了，不应该在内部的吗，与应用切割了**」。

### 这个项目有两种滚动写法（这次才搞清）

| 模式 | 用的页面 | 滚动条归属 |
|---|---|---|
| **`AppLayout`**：外层 `height:100vh; overflow:hidden` + 内层 `.main-content { overflow-y:auto }` | 学程 / 社区 / 首页 | **内容区**（在应用里） |
| 普通页：`min-height:100vh` → **窗口滚** | **设置页** / Profile / … | **html**（贴窗口最外缘） |

在**无边框的桌面壳**里，窗口级滚动条贴着窗口边、看着和应用是两截。
改成 AppLayout 那种写法后：**窗口级滚动条消失，滚动发生在应用内**；
顶栏也因此天然固定（它在滚动容器之外，**不需要 sticky**）。

### 一个设计取舍：sticky vs fixed

一开始用 `sticky` 固定顶栏，改内部滚动后**撤掉了** ——
顶栏已在滚动容器之外，sticky 是多余的。**能用结构解决的，别用定位技巧。**

## 二十、自定义快捷键（完整架构）

用户：「现在要搞一个自定义快捷键，在设置里面搞，你架构一下」，随后定：
**应用内生效** + **跟随账号**。

### 目录

```
frontend/src/shortcuts/
  combo.js              组合键规范化 / 解析 / 匹配
  registry.js           动作清单（唯一数据源 · 25 个动作）
  store.js              绑定状态 + 本地缓存 + 账号同步 + 冲突检测
  manager.js            分发器（全站唯一 keydown 点）
  ShortcutsSection.vue  设置页 UI（录制态 + 冲突提示）

backend/sql/user_shortcuts.sql   表（照 user_theme_settings 先例）
backend/routers/auth.py          GET/PUT /auth/shortcuts
```

### 为什么要有「分发器」这一层

键盘事件原来散在三处，先后**取决于监听器注册顺序**：
`desktop/index.js` 的浏览器快捷键拦截、`GlobalSearch.vue` 的 Ctrl+K、各组件的 `@keyup.enter`。
**收进一个分发器后，优先级是写在代码里的常量**，不是运行时的偶然：

```
① 输入态保护（无修饰键放行，否则打字被吃）
② 内置屏蔽（F5/Ctrl+R/Ctrl+P/Ctrl+U/F12）
③ 用户绑定   ④ 默认绑定
```

⚠️ **②必须排在①之前** —— 否则在输入框里按 F5 会走「输入态放行」那条路，页面被刷新。

**已拆掉两处旧监听**：`desktop/index.js` 的拦截 → 变成 `sys.block*` 内置动作；
`GlobalSearch.vue` 的 Ctrl+K → 变成 `action.search`，**用户现在能改它了**。

### 存储：localStorage 缓存 + 账号权威

合并规则：**账号里有的以账号为准**，账号里没有的保留本地 ——
「没登录时改过、然后登录」不会把本地改动吞掉。

### ⚠️ 我编了一个不存在的功能

按惯例加了 `action.theme`「切换深浅色」。查了才发现 —— **项目 09-03 就去掉了浅/深开关**，
外观改成四轴定制（背景色+组件色+主题色+字体色），theme store 里根本没有这个方法。
**那个动作按了不会有任何反应**。已删，并在代码里留了说明。

## 二十一、桌宠（桌面级）

用户：「加一个桌宠功能」→ 选 **B（桌面级：独立透明置顶窗口，关掉主程序也在）**。

### 产物

```
ui/pet.html                  桌宠窗口本体（透明·可拖拽·单击·菜单·聊天·通话）
ui/pet/*.webp                小基形象 5 态（136KB，**不用 PNG 的 1MB** —— 安装包才 1.4MB）

src-tauri/permissions/       app 命令的 ACL 声明（见下）

```

### 交互（全部在桌宠窗口内，一个都不打开主程序）

| 操作 | 效果 |
|---|---|
| 单击 | 拍拍它，小基冒一句话（本地语句池，不联网，立刻可用） |
| 拖动 | 换位置 |
| 右键 / 长按 | 菜单：💬 说句话 · 📞 语音通话 · 👋 先躲起来 |

| 右键（通话/聊天中） | 不响应，避免误触 |

### ⚠️ 三个坑（都属于「第一次真正用到才发现」）

**1. dev 配置把窗口数组整个盖掉了**

`tauri.dev.conf.json` 里**自己也有一份 `windows` 数组**（只有 main 一项）。
Tauri 合并配置时**数组是整体覆盖**的 —— 所以 **dev 环境永远没有桌宠窗口，生产构建却有**。
这是最难查的一类「dev ≠ prod」：按 dev 的表现去查，永远查不到。
两边现在都补齐了。

**2. `set_pet_visible not allowed. plugin not found` —— ACL 拒绝**

Tauri v2 的 ACL **只管插件命令**（`core:*`、`window-state`），
**app 自己 `#[tauri::command]` 定义的命令不会自动获得许可**。
**本地页面**调用一般没事，但本项目主窗口加载的是**远程站点**，远程内容受 ACL 管辖。

报错里的 **"plugin not found" 极具误导性** —— 它让人以为是插件没装，
实际是「这个命令根本不在许可名单里」。

修法：新建 `src-tauri/permissions/app-commands.toml` 声明 `commands.allow`，并在 capability 里引用。
**顺带查明：`save_file` / `open_external` / `app_version` 一直是同样的状态** ——
只是从来没人真正点过导出（09-27 待办里就写着「桌面版实际体验用户还没反馈过」）。

**3. 我自己误删了 token 桥**

删 `pet_action`（因为桌宠改成不打开主窗口，它成了死代码）时，
我把删除区间划到了 `fn main()` —— **中间的 token 桥整段被吞掉**（11 个编译错误）。

**和上午误删 `_create_wechat_account` 是同一类错误。**
教训：**删除区间不要拿「下一个函数」当终点，要拿注释/标记**；
而且删完立刻编译，不要等。

### 桌宠的两条技术约束（决定了它能做什么）

| 约束 | 后果 |
|---|---|
| 桌宠窗口是**独立 origin**（本地页），与主窗口（远程站点）**不共享 localStorage** | 拿不到登录 token |
| 后端 CORS 白名单里只有 `jizhi-learn.com` 那几个源 | 直接 fetch 会被浏览器拦 |

**做法**：主窗口把 `{token, apiBase}` 推给壳（存内存不落盘），桌宠问壳要；
后端 CORS 加 `http://tauri.localhost` / `tauri://localhost`。
`apiBase` 也一并传 —— 开发是 `localhost:8000`、生产是 `api.jizhi-learn.com`，
写死在桌宠的 html 里必然有一边是错的。

### 拖拽 / 点击 / 长按三者共存

都从 `mousedown` 开始。**关键是 mousedown 时不能立刻 `startDragging`** ——
一旦交给系统拖拽，webview 就收不到后续事件，长按和点击都没了。
所以先起一个 550ms 计时器，**真移动了（>4px）才把控制权交给系统**。
