## 一、双主题（用户定调：就两档，不要网页端四轴）

| 项 | 实现 |
|---|---|
| 模式 | `system`（默认）/ `light` / `dark`，存 `uni.setStorageSync('jizhi-theme-mode')` |
| 系统监听 | `uni.onThemeChange`；**需 `manifest.json` 开 `darkmode: true`**，否则读不到系统主题 |
| token 层 | `App.vue` 全局 `<style>`，两套值挂 `.t-dark` / `.t-light`，约 25 个 |
| 挂载 | 页面根节点 `:class="themeStore.rootClass()"` |
| 入口 | 设置页「外观」分段控件 |

深色那套**不是照搬原值**——顺手把上面四个问题一起修了：卡片填充 6%→8.5%、描边独立成 13%、文字四档整体抬亮（`#475569` 2.36:1 → `#5c6b82` 3.30:1）、补上缺失的氛围层。

### 原生导航栏联动（不做会割裂）

`uni.setNavigationBarColor` **只作用于当前页**。用户改完主题返回其他页面时，那些页面的原生栏还停在旧色，顶部一条割裂边。解法是 `main.js` 一个全局混入：

```js
app.mixin({ onShow() { useThemeStore(pinia).syncChrome() } })
```

比在 42 个页面各写一遍 `onShow` 可靠。

## 二、全量 token 化

```
984 处硬编码 hex  →  1346 处 var()
残留 28 处为有意保留（品牌渐变配白字、模型厂商品牌色等内容色）
```

### ⚠️ 迁移时拦下的两个硬约束

**1. 颜色替换只能作用于 `<style>` 块。**
项目里有 **93 处颜色是 JS 数据**，而 `agent-center` 两个文件有 `hexToRgba()` 会**解析 hex 字符串**——盲替会把它们直接打断。脚本必须按 `<template>/<script>/<style>` 切段，只改 style。

**2. 同一个 rgba 值在 `background` 位和 `border` 位要映射到不同 token。**
`rgba(255,255,255,0.06)` 作填充是「面」、作描边是「线」。不区分的话卡片边界会消失——而边界消失正是这次要修的问题之一。

## 三、分类色板与页面色调

**分工边界（写进手册了）**：语义色只表**状态**（对错/警告/分数档位），分类色只表**归属**（模块/学科/分类）。**两者严格分开。**

9 个色相：`red` `orange` `amber` `green` `teal` `cyan` `blue` `violet` `pink`

**`--tone` 按路由推导**：`stores/theme.js` 里一张 `ROUTE_TONE` 前缀表，根节点挂 `tone-xxx` 类，页面内标题统一引用 `var(--tone)`。于是每个模块自动带自己的色，不必逐页写死。

### ⚠️ 两个自己造的坑

1. **`.tone-*` 规则必须排在 `.t-dark`/`.t-light` 之后** —— 两者特异性相同，靠源码顺序决胜。写在前面会被 `--tone` 的兜底值覆盖，色调永远出不来。
2. **`rootClass()` 必须是函数，不能是 computed** —— 路由是页面级状态，computed 会被 Pinia store 单例缓存，第二个页面拿到的还是第一个页面的色调。

## 四、浅色模式的坑（用户第二次反馈：「输入框在浅色的时候也这么黑」）

### 根因：深色 rgba 是整类漏网的

```scss
.input-wrap { background: rgba(15,23,42,0.92); }   /* 首页底部输入栏 */
```

上一轮的迁移规则只覆盖了 `#0f172a` **十六进制**和**白色叠加**，`rgba(15,23,42,...)` 这类**深色 rgba 从来没进过匹配范围**。全项目共 **7 处**，全是吸底操作栏和弹窗：首页输入栏、考试交卷条、评估页 ×2、学程 ×3。

**修法**：新增 `--bar` token（半透明吸底栏），另 3 处 `rgba(30,41,59,...)` 归到已有的 `--sheet`。

### 另外三处

- **`.glass-card` 定义了 `--shadow` 却从来没用过**。浅色主题本来就靠投影分层（白卡在白底上永远拉不开对比度），这条一漏，卡片彻底融进背景（1.13:1）。
- **输入框只有 1.08:1**。浅色 `--surface-2` 0.035→0.055，`--line` 0.10→0.12，3 个缺描边的输入框补上描边。
- **9 个分类色的浅底全是 0.10 alpha**，在白底上合成出来**全是同一个米白**，色相彼此分不出来，等于没上色。提到 0.18 才拉得开；代价是橙/琥珀底色变深后和自身颜色撞了，把这两个色相各压深一档。

### 顺带修的两处

- **登录页 `placeholder-style="color:#64748b"`** —— 写死在**模板**里，同样不在 `<style>` 块内，也是漏网的
- **6 个裸输入没声明背景** —— 微信原生 `textarea` 会用自己的默认底色，**深色模式下反而发白**

### 对比度审计（新增 `contrast-audit.mjs`）

改完后两套主题全部达标：

```

深色  主文字 12.15 / 次 6.87 / 弱 4.15 / 占位 3.62 / 占位×输入框 3.05
分类色 9 个色相 × 同色浅底：两套主题各 9/9 通过（3.02 ~ 4.35）
```

顺带查出**深色模式**一个没人报过的问题：占位文字在输入框上只有 2.21:1。

### 截图管线的三个技术点

1. **不用 `chrome --screenshot`，用 CDP**。前者截的是固定窗口高度，内容只占顶部一小条；CDP 可以先量 `document.scrollHeight` 再按真实高度截。
2. **登录态**：项目 47 条路由只有 `/` 和 `/login` 公开，其余全需登录。用 `JWT_SECRET` 自签了一个 6 小时测试 token（**用户明确点头后才做**），通过同源种子页写进 localStorage。
3. **浅色主题必须注入 CSS 变量，种 localStorage 没用**——登录后 `loadFromAccount()` 会从**数据库**拉主题覆盖本地缓存，而该账号库里存的是深空蓝。

### 截图环境的两个假象（**不是产品的 bug**）

- **侧栏渲染成黑块**：侧栏用 `backdrop-filter: blur(24px)`，无头 Chrome 缺 GPU 合成会把模糊层渲染成纯黑。注入时关掉模糊即可。
- **`17-评估表` 是加载中**：AI 生成诊断没回来就截了，加长等待后正常。

## 教训（我自己的）

**这一轮我连续写错了四次校验脚本**，每次都得出过错误结论：

| # | 错误 | 后果 |
|---|---|---|
| 1 | `grep ... \| head` 的退出码取 `head`（永远成功） | 误报「有残留引用」，实际 0 残留 |
| 2 | 校验锚点没按文档惯例去点号 | 误报「191 条锚点全对不上」 |
| 3 | 同上，又折叠了空格（GitHub 是每个空格各变一个连字符） | 再次误报 |
| 4 | 正则 `\(` 匹配字面括号而非点号 | 6 处修改**静默 SKIP**，而我上一步已报成「已完成」，是逐个核对文件内容时才发现 |

另外用 `sed` 同步审计脚本时只改中了一半，导致有一轮报出的对比度数字**是假的**（脚本和 `App.vue` 不一致）。

**共同点：都是「校验工具本身错了」，而不是被校验的对象错了。** 教训是——**报「通过/失败」之前，先确认校验器本身是对的**；尤其在用一行 shell 判断成败时，注意管道退出码取的是最后一个命令。
