## 一、小基发送失败（三个真 bug）

### ① `agentKey is not defined` —— 所有文本消息都发不出去
用户 console：`ReferenceError: agentKey is not defined at streamXiaojiChat (XiaojiCall.vue:2028)`

- **根因**：09-10「删呼叫对象下拉框改自动分流」时删掉了 `agentKey` 变量，但新写的 `streamXiaojiChat` 里漏改了一处引用。该函数是本次未提交改动里新增的（HEAD 里没有），改名时漏掉
- 聊天链路必走这行 → 抛错被 catch 吞成「发送失败，请重试」→ **与网络无关，任何文本都发不出去**
- **修复**：`agent: agentKey || undefined` → `agent: pendingAgent || undefined`

### ② `/auth/status` 400（登录时报「更新在线状态失败」）
- **根因**：`auth.py` 那行用了 service_role（注释写着 `# ← 改这里`），但 **profiles 表从没给 service_role 授 UPDATE 权**。实测 service_role 打 PATCH → `403 permission denied for table profiles`；anon key → `200` 且值真变（已还原）
- **修复**：改回全站 95 处在用的 `get_supabase_headers()`

### ③ `WaterBackground.vue:181` mousemove 报 null
- **根因**：卸载时 Vue 先把模板 ref 置 null，`onUnmounted` 里 `if (container)` 恒假 → 监听器永远摘不掉
- **修复**：挂载时把元素存进局部变量供卸载时摘监听 + 处理器判空

### 验证
py_compile ✅ / import ✅ / `update_status()` 真调 `{'success': True}`（已还原）/ dist 中 free `agentKey` 已消失（只剩路由参数与 `params.agentKey` 成员访问）/ 全文件未声明标识符扫描无其他残留 / vite build 7.16s

## 二、代码沙箱：Java 全线不可用

### 现象
四种语言里**只有 Java 坏**（Python/C/C++ 正常），实测 `POST /subject-plan/code/run`：

| 语言 | 结果 |
|---|---|
| Python | `{"output":"2\n","exit_code":0}` ✅ |
| C++ | `{"output":"4","exit_code":0}` ✅ |
| Java | `{"output":"代码执行服务暂不可用: All connection attempts failed","exit_code":-1}` ❌ |

### 根因链
1. 本机只有 winget 的 gcc/g++，**没有 javac/java** → 本地编译分支返回 `None`
2. 回退 Piston → `PISTON_URL` 默认 `localhost:2000` → **无服务**
3. 而前端 `CODE_LANGS` 硬编码四种语言，从不问后端 → Java 永远选得到、永远失败

### 修复过程
- **winget 装 JDK 是假成功**：MSI 请求管理员提权，非交互会话里 UAC 没弹出来，安装器根本没执行（MSI 日志没生成、注册表/磁盘/`winget list` 三处查无此物），winget 却报「已成功安装」
- 改走**免管理员 zip**，解压到代码里本来就预留好的 `backend/utils/jdk/`（OpenJDK 17.0.20.1 LTS），`backend/utils/jdk/` 已加进 .gitignore

### 顺带挖出两个 Java 真 bug（都是修 Java 时实测出来的）
1. **中文源码必然编译失败**：源码按 UTF-8 落盘，`javac` 跟随平台编码（中文 Windows 是 GBK）→ 含中文注释/字符串的代码 exit=1 且只报「找不到主类」→ 补 `-encoding UTF-8`
2. **编译错误被吞**：javac 结果丢弃、直接跑 java → 报「找不到或无法加载主类」而非真诊断 → 补 returncode 检查，与 C/C++ 那条路对齐

### 验证
四语言全 PASS；java 中文输出 `你好，世界` exit 0；类型不匹配报 `错误: 不兼容的类型: String无法转换为int`（编码链路按字节验过）

## 三、出题提示词：题型轴 × 学科轴重构 + 编程题质检闸

### 检验（用户：「检验提示词，不能固定某个方面，要适配，以及要全面完善」）
逐题型实测六种题型，**固定模板造成的实际伤害**：

| 题型 | 改前 answer | 应为 |
|---|---|---|
| **判断题** | **`A`** | 正确/错误 |
| **计算题** | **`A`** | 数值/表达式 |
| **编程题** | 裸函数，无 starter_code/test_cases | 完整可跑程序 |

六种题型返回字段完全一样（`额外字段=[]`）——判断题和计算题的答案双双变成选项字母 `A`，就是因为共用 schema 硬塞了 `options:{A,B,C,D}`。

### 改动
- `QTYPE_SPECS`：7 种题型各自的「任务 + 答案写法 + 输出字段表 + 禁止项」。只有选择题带 `options`
- `SUBJECT_DISCIPLINE`：11 个学科各自的用词/例子/禁止项
- `ANGLES_COMMON` / `ANGLES_CS`：按学科选角度池，**取代**旧的「编程角度再转译」补丁
- `PROGRAMMING_JSON_TEMPLATE`：编程题沿用 `seed_all_banks.py` 里**已有的**标准 schema（题库 19,338 题就是它生成的），类型名改回题库的 `programming`
- 落库补 `starter_code` / `test_cases`（之前整体丢弃）

### 编程题质检闸（改提示词解决不了「模型自己算错数」）
实测 **17 条用例只有 13 条跟它自己的参考答案对得上（76%）**。生成后真跑一遍参考答案：通过→落库；不一致→带实跑证据让模型修（≤2 轮）；仍不过→502 如实报错。

> 修的过程中发现**修复轮从来没真正生效过**：修复调用是**不带 schema 的全新对话**，模型只能自己编格式（返回 `reference_solution`/`sample_input` 之类），每轮都白修。补上 schema + 键名归一（`expected`/`sample_output` → `output`）后才起作用。

### 验证
判断题 `错误` / 计算题分步过程 / 编程题 `programming` + 5 字段 content + 3 用例 + starter_code + 可跑程序；**落库题用例通过率 76% → 100%（15/15）**；独立计算校验一致（`2^10 mod 1000=24`）；生成耗时 6s → 9s

### 评估 schema 同步改（`EVAL_SPECS`）
旧版所有题型共用一段 `detailed_analysis` 自由文本。现在按题型给「批改重点 + 专属结构化字段」：选择题 → `option_analysis`（实测拿到 A/B/C/D 逐项对错）、计算题 → `steps`（分步对错）、简答题 → `key_points`；编程题明确「有测试用例时已由沙箱判分，不要推翻判分结果」

### 生成的编程题现在真能跑、能判分
- **后端**：`/code/submit` 以前只查本地题库 → 生成题必然 404。现在题库优先、**回落到 Supabase `questions` 表**；题型闸放宽为 `programming`/`coding` 都收；修了判分只认 `expected_output`/`expected` 而生成题写 `output` 的隐藏 bug；`test_results` 补 `expected`
- **前端**：`DoQuestion` 编程题从光秃秃文本框 → 代码编辑器 + ▶运行（stdin 可填）+ 样例展示 + 逐点 AC/WA/RE/TLE 徽章 + 失败点显示「期望 X · 实得 Y」；有测试用例走沙箱判分，不再交给 AI
- **实测**：正确代码 AC 3/3 score 100 / 错误代码 WA 3/3 / 运行时错误 RE 3/3
