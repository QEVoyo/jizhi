## 教训

1. **把「最近在做的事」当成「用户要的东西」—— 今天栽了两次。**
   300 字简介前两版都在写「桌面端这个客户端怎么做的」，而用户要的是「为什么做这个平台」。
   **动手前先对齐：这份东西给谁看、要回答什么问题。**
2. **文档里的「现状陈述」是最容易过期的一类文字。**
   我拿报告 §（十一）的「视频生成目前在线上不工作」当事实 —— 那句话写于 10-02，
   而项目是按天推进的。**凡是写「目前 / 尚未 / 待…」的句子，重新打开报告时必须逐条复核。**
3. **校验和是「同名不同物」的唯一防线。** 安装包有三个同名副本，
   正是 md5 一致（`bf8c42f4…`）才敢断定拿的是含桌宠那版。
4. **打包前先扫凭证。** `.env.local` 里的 `VERCEL_OIDC_TOKEN` 差一点随源码包交出去。
   **「源码包」不等于「可以交的源码包」。**
5. **误报会掩盖真报。** 首轮敏感串扫描 13 个命中全是 `task-` / `mask-` 里的 `sk-`。
   换成精确模式后是 0 —— **报数之前先看一眼命中的是什么**（09-30 那条
   `min-height:100vh` 教训的变体，又踩了一次）。
6. **材料的一致性，是独立于内容质量的一关。**
   16,889 与 19,338 差一个数字，但评委交叉核对时看到的是「不严谨」——
   这种分丢得最冤。

## 一、先量，别猜

用户说「消息中心非常乱，一开始没有设想好消息队列」。动手前把现状量了一遍（**用 `_devtools/supabase-h3-bridge` 连的服务端 —— 校园网又对 `*.supabase.co` 做 SNI 阻断了，直连 `WinError 10054`**）：

```
notifications 全表 5 行：system 3（最近今天 12:07）· chat 2（最近 08-24）
前端却有 10 个 Tab，其中 6 类一行数据都没有
```

翻代码查出**四个结构性问题**：

1. **三套读法**：`unread/summary`（只查未读，点一下就没）、`sidebar-badges`（chat 按**发送者去重**）、前端直接 fetch 公告 —— 侧边栏和消息中心的数字**必然对不上**
2. **五个写入方，两个绕过公共入口**（`tools.py` 胶囊、`daily_generator.py` 自己拼 dict 插表）
3. 🎯 **聚合更新是死的，而且静默了两个月**：`_upsert_notification()` 的 PATCH 里写了 `updated_at`，而**这张表根本没有这一列** → 每次 400 → 返回 False → **而调用方不检查返回值**。铁证：接收者 `540b599b…` 的私信通知冻结在 08-24、`msg_count=1`，而同一发送者后来还发过 3 条（最后 10-02）
4. **公告是异物**：走另一张表、`is_read: true` 写死、徽标拿**总数**当未读数

**顺带查出一个从没被发现的 bug**：`/post/:id` 这个路由**根本不存在**，而「收藏」页和「我的帖子」一直在 `router.push('/post/xxx')` —— 点了没反应。

## 二、设计（`message_center_design.md`，实施契约）

产出 **66 个消息点 / 9 个大类**，几个关键决定：

- **三条已读路径**：A 点消息→看详情→已读 · B **走到目标页即已读**（挂全局路由守卫，一处覆盖全部；但 `system`/`todo` 两组不参与）· C 直接标记
- **待办型**（好友请求/题集分享/管理员队列）：**处理完才算已读**，看见不算 —— 否则角标没了事还在
- **详情是毛玻璃居中弹层**（不是右侧抽屉，全站没这种形态）
- **配色**：九个大类固定语义色（5 个沿用线上已有）+ 组内派生渐变。⚠️ 公式只有**一份实现**（后端 `derive_color`），前端与预览页都从 `/messages/registry` 取，不重写

## 教训（本节）

1. **「乱」要先量再判。** 用户说乱，我量出的是"全表 5 行 + 两套算法 + 一个静默两个月的 PATCH"——**乱的是结构，不是数据**。
2. **静默失败的第三个变体**：这次是"写了一个**不存在的列**"。前两次是 42501 权限、非 200 降级成空。**共同点都是"返回值没人看"。**
3. **配色公式只能有一份实现。** 第一版按"每步 6°"算，13 个点的 learning 组跨到 ±36°，**第一个点变成了黄色** —— 大类都认不出来了。改成组内总跨度固定，并把公式放在后端由 `/messages/registry` 下发。
4. **用户四次纠正都是对的**：简介写成了"桌面端怎么交付的"、详情做成了右侧抽屉、"每日推荐"被我写成三个链接（其实是**可执行的任务**）、学程漏了**任务完成**本身。**我每次都在"实现我脑子里的图"，而不是"实现他说的东西"。**
5. **顺手挖出来的两个老 bug**（`/post/:id` 不存在、`delete_content` 不通知）都不是这轮引入的，是这轮**读代码读出来的** —— 重构前先把要碰的地方读透，回报率很高。
