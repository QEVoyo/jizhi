## 白天段:播放器呈现管线重写(用户拍板「要不就重新写整个页面」)

### 背景
用户反馈「点击视频进入画面还是没显示,改了也没用」→ 不再走排查往返,直接按用户授权重写播放器呈现层(保留全部分镜演出逻辑与数据契约)。

### 重写前代码里确认的 3 个雷(疑似「有声音没画面」组合成因)
1. **全屏骨架遮罩卡画面**:退场只认 `canplay`。浏览器音频已播但只发 `playing`/`timeupdate` 不发 `canplay` 时,`audioReady` 恒 false → 92% 不透明遮罩永远盖住画面(6s 兜底自身还要再 play 一次,路径不干净)
2. **舞台高度依赖 `aspect-ratio`**:父容器宽度异常时舞台 0 高,里面所有 `absolute; inset:0` 画面全塌
3. **类名冲突真 bug**:`.vlp-bar` 被「控制条」和「骨架 shimmer 条」两套 CSS 定义,shimmer 样式后写覆盖控制条(10px 高渐变条)

### 重写方案(`components/VideoLessonPlayer.vue`)
- **画面无条件立即渲染**:彻底去掉全屏遮罩——加载=右下角小 pill、音轨出错=底部横幅(带 ↻ 重试)、autoplay 被拦=半透明大播钮(画面仍可见)、缓冲=角标。任何环境下一点击画面必在
- **16:9 高度万金油**:`.vlp-frame` padding-top 56.25% + 舞台 absolute 铺满,不依赖 aspect-ratio
- **就绪多路信号**:canplay / playing / timeupdate / readyState≥3 / 4s 兜底,任一即 ready
- **CSS 降险**:组件内 backdrop-filter 全去、color-mix 换固定 rgba(该组件本就是固定深色「视频屏幕」,不随主题);`rotate` 误写已修
- 控制条改名 `.vlp-ctlbar` 与骨架条解耦;props/expose(stop/start)不变,DoQuestion/VideoDetail 零改动

### `views/VlpDebug.vue` 升级
- 数据源改走真实 API(proxy):广场第一个 ready 视频 → `/video/{id}/detail` 拿完整 script(旧版硬编码的样片 ID 已被删会 404);支持 `?id=` 指定
- 自检加浏览器能力探测:aspect-ratio / color-mix / backdrop-filter / 正则 lookbehind

### 验证
- vite build 1.42s 通过(修复 1 个 CSS 笔误后)

### 用户验收动作
