## 分页 206 bug 修复（用户实测「一条历史记录都没有」）

- **现象**：08-24 上线的聊天记录分页，用户实测先「更早消息加载不出」、后「一条历史记录都没有」；真实账号（34 条消息）limit=30 返回 0 条、limit=50 返回 34 条
- **根因**：PostgREST 在 `Prefer: count=exact` + `limit` 且结果被截断时返回 **206 Partial Content**（不是 200）；端点只认 200 → 206 被当成错误返回空数组。limit ≥ 总数时无截断返回 200 所以「正常」。此前所有冒烟测试恰好都落在 0 行（200）或测试种子未写入（FK）的场景，未触发 206 分支
- **排查过程**：测试种子被 `xiaoji_messages → profiles` 外键拦截（两轮误判）→ Supabase 直连逐子句隔离确认库层正常 → 进程内复现正常而运行中服务异常 → 指纹测试（limit=30 空 / limit=50 正常）锁定 206
- **修复**：`routers/community/xiaoji.py` 接受 `200/206`（一行）；真实账号验证：page1 30 条 total=34 has_more=true，page2（offset=30）4 条到最早「你好」
- **教训**：PostgREST count=exact 截断响应是 206；端点测试要用有真实数据的账号（自签 JWT 可用任意 sub 模拟）

## 小基「语音通话」全新功能（千问 Qwen-Audio-3.0-Realtime 实时语音对话）

### 背景
用户指出：语音通话和语音读文字是两回事，应是独立界面（原「语音通话」按钮只是跳去聊天页）。并指定语音对话模型用千问 `qwen-audio-3.0-realtime-plus`（key 存 `.env` DASHSCOPE_API_KEY），不用讯飞 ASR→DeepSeek→讯飞 TTS 三段链路。

### 方案
千问 realtime 是语音到语音原生模型：自带 server_vad 断句、自动打断、直接输出语音。后端只做薄中转：
浏览器 ↔ `WS /xiaoji/call-ws`（鉴权 + 小基人设注入 + 历史上下文 + 消息落库）↔ 千问 realtime WS

### 后端（`routers/xiaoji.py`）
| 项 | 说明 |
|---|---|
| `WS /xiaoji/call-ws` | 鉴权（WS 不能带 Header，token 走 query：自签 JWT → Supabase 双验证）；读小基配置（名称/语气风格注入 instructions，讯飞音色映射千问音色 longanqian 等，主动问候开关）|
| session.update | `modalities: [text, audio]`、`input_audio_format: pcm`(16k)、`output_audio_format: pcm`(24k)、`turn_detection: server_vad (silence 800ms)`、max_history_turns 20 |
| 上下文 | 最近 6 条聊天记录预载为 conversation.item；问候 = 注入「电话刚接通」触发器 + response.create |
| 双向中转 | 音频帧→`input_audio_buffer.append`；`interrupt`→`response.cancel`（仅在有进行中回复时发，空闲 cancel 会触发 invalid_request_error）；30s 静默 WS ping 保活；30 分钟上限 |
| 字幕/落库 | `input_audio_transcription.delta`（stash 字段）→ 我说话实时字幕；completed→存 user 消息(kind=voice_call)；`response.audio_transcript.delta`/`audio.delta`→回传；done(completed)→存 assistant 消息 |
| 错误策略 | 千问客户端错误（如空闲 cancel）忽略不打扰通话；server_error 才断开 |

### 前端（`views/XiaojiVoiceCall.vue` 🆕 + 接线）
- 独立通话界面 `/xiaoji/voice-call`：小基头像 + 脉冲光环 + 通话计时 + 字幕区（我/小基实时字幕）+ 静音 + 红色挂断按钮
- 音频：麦克风 16k PCM16（AEC 回声消除+降噪）持续发帧；千问输出 24k PCM16 用 WebAudio 排队播放（GainNode 音量读设置页）
- **防回声**（官方示例同款策略）：小基播报期间停止发帧；播报中检测到用户持续说话（RMS>0.03×3 帧）→ 本地抢话打断：发 interrupt + 清空播放队列 + 丢弃在途音频（expectSilence，因千问 cancel 只停生成不停已生成音频的发送）
- 入口：设置页「语音通话」→「拨打」跳通话页；聊天页工具栏 + 电话按钮；命名册 pageMeta 收录（aliases: 通话/打电话）
- 智能体中心触点：小基新增「语音通话」触点（kind=voice_call）

### 排障记录
1. `extra_headers` 参数不存在（websockets 15 新 asyncio 实现改名 `additional_headers`）
2. 测试发完语音就停发帧 → 千问 VAD 等不到句尾静音不触发回复；真实麦克风持续采音无此问题（测试补 2s 尾静音）
3. 空闲时 response.cancel → `invalid_request_error "Conversation has no active response"` → 改为有回复才 cancel + 客户端错误忽略

### 验证
- 裸协议探测（直连千问）确认全部事件名/字段：stash 渐进文本、transcript 最终文本、audio.delta base64 PCM24k
- 端到端实测（自签 JWT + SAPI 真实中文语音「你好小基，我最近数学考得不太好，你能安慰我一下吗」）：问候语音 ✅ 渐进字幕 ✅ 完整识别 ✅ 文字+语音回复 ✅ done ✅ 挂断 ✅
- vite build / py_compile 通过
- 遗留：① 浏览器真机体验（麦克风权限/回声/抢话）待用户确认 ② 千问实时语音按 token 计费，注意用量 ③ 通话中「语音播报开关/语速」设置未接入（音色已映射）
