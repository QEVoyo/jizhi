## 小基（Xiaoji）系列修复与新功能

### 1. 前端 API 断链修复

**问题**：`api/xiaoji.js` 写成"community 前缀 + path 参数"杂交体，后端 community 包用 query 参数、顶层 /xiaoji 用 path 参数，两边都对不上 → 小基设置页/语音页运行时 404。

| 函数 | 之前（404） | 之后 |
|---|---|---|
| getXiaojiMessages | `/community/xiaoji/messages/{userId}` | `/community/xiaoji/messages?user_id=` ✅ |
| getXiaojiConfig | `/community/xiaoji/config/{userId}` | `/community/xiaoji/config?user_id=` ✅ |
| updateXiaojiConfig | `PUT .../config/{userId}` | `PUT .../config?user_id=` + body ✅ |
| clearXiaojiMessages | `DELETE .../messages/{userId}`（不存在） | `DELETE /xiaoji/messages/{userId}`（顶层已有）✅ |

### 2. 上下文记忆修复（RLS）

**问题**：小基无上下文记忆。日志显示 `保存用户消息状态: 401` —— `xiaoji_messages` 表存在但 RLS 开启且无策略（读返回空、写被拒）；全项目 SQL 无该表 DDL。后端本身有记忆逻辑（查最近 10 条 + 存储），匿名 key 访问需策略放行（与 community 其他表惯例一致）。

**修复**：新增 `backend/sql/xiaoji_rls_policies.sql` — xiaoji_messages / xiaoji_config 两张表 RLS 放行策略（用户已在 Supabase 执行）。

### 3. 进入页面定位最新消息

**问题**：进入语音页停在顶部。`loadMessages()` 中 `loading.value = false` 在 finally 里、滚动之后才执行 → 滚动时消息未渲染，scrollHeight 无效。

**修复**：先关 loading → nextTick 等渲染 → 滚动；首次加载用瞬时滚动（临时禁用 smooth）；删除重复的 `watch(messages)`。

### 4. 聊天日期分隔线

相邻消息跨天时插入居中日期分隔：今天 / 昨天 / M月D日 周几 / 跨年带年份。

### 5. 实时模糊搜索 → 独立搜索页

**迭代过程**：
- 初版内嵌搜索条 + 手动搜索 → 用户要求实时 → 防抖 350ms 实时查询 + 抖音风搜索历史
- 用户要求独立搜索页 → 重构：

```
聊天页 🔍 → /xiaoji/search 搜索页（新建 XiaojiSearch.vue）
  ├─ 输入自动聚焦，边输入边实时模糊搜索（防抖 350ms + 过期结果丢弃）
  ├─ 结果 = 一条条记录：头像 + 我/小基标签 + 时间 + 内容摘要（用户和小基的消息都搜）
  ├─ 输入为空 → 搜索历史标签（localStorage，去重最近优先，最多 10 条，可清空）
  └─ 点结果 → 跳回 /xiaoji/call?highlight={msg_id}
                ├─ 自动滚动定位到该消息（居中）
                └─ 黄色高亮闪烁 2.4s 淡出
```

### 6. 后端搜索通配符 bug（关键）

**问题**：搜索全部失败。实测对照：PostgREST 模糊匹配通配符是 `*`（内部转 SQL 的 `%`），代码写 `ilike.%kw%` → **500** → 后端静默返回空列表。

| 写法 | 实测结果 |
|---|---|
| `content=ilike.*哈哈*` | 200，命中 ✅ |
| `content=ilike.%哈哈%` | 500 ❌ |

**修复**：`routers/community/xiaoji.py` + `routers/xiaoji.py` 两处改为 `ilike.*{kw}*`；同时给 community messages 端点补上 `search` 参数。
