## 一、先确认现状（用户的判断是对的）

九颗星球原来的构成只有三样：`SphereGeometry` + 纯色 `MeshStandardMaterial`（`color` + 同色 `emissive 0.55`）+ 一层 0.14 透明度的同色壳当"大气"，每三颗加一个实心 `Torus` 光环。
**没有贴图、没有法线、没有云层**，凑近看就是一个光滑的彩色球。

技术储备是够的：three r185，已开 ACES tone mapping + antialias，`MeshPhysicalMaterial`／自定义 shader ／`onBeforeCompile` 都能直接用；地表可以完全程序化生成，不需要下载任何贴图资源。

## 三、实现

### 1. 球面噪声（关键做法）
球体贴等距圆柱投影图有两个老毛病：**左右接缝对不上、两极挤成麻花**。
解法不是去修接缝，而是**不按 (u,v) 平面采噪声**——每个纹素先算出它在球面上的真实单位方向，再拿这个方向去采 3D 噪声。噪声本身就定义在球面上，接缝与极点问题自然都不存在。

噪声用 3D 值噪声 + fBm（分形叠加），另加一个**脊状噪声** `1-|2n-1|` 专门用来出裂纹／山脊／熔岩缝。

### 2. 六种地表生成器 × 九套配方

| 生成器 | 用在哪 | 特征 |
|---|---|---|
| `terran` | 知识星系、学习人格 | 大陆 + 海洋 + 雪线随海拔上抬的极冠 |
| `gas` | 能力雷达、兴趣星云 | 纬向条纹（纬度先被湍流扰动，不是死板直线）+ 大红斑 |
| `ice` | 学习节奏、AI 洞见 | 冰板块 + 脊状裂纹 |
| `rock` | 认知偏好 | fBm 地形 + 16 个陨坑（坑底压暗压平、坑缘隆起提亮） |
| `lava` | 易错地图 | 冷壳 + 发光熔岩缝（只有裂缝发光，不是整颗均匀发亮） |
| `ocean` | 成长轨迹 | 全球皆水 + **域扭曲出的洋流涡旋** + 大极冠 |

同一种生成器配不同 `seed`／云量／海平面／条纹数／裂纹密度，九颗不重样。

### 3. 另外三件事
- **大气**：旧的"大气"是个等比放大的**纯色透明球**，渲染出来是个平圆盘而不是辉光。换成**菲涅尔着色器**——正对镜头的中心透明、越靠边缘越亮，星球外缘才真有一圈大气光。
- **云层**：独立一层球，转得比地表快（0.016 vs 0.010）→ 有视差。贴图是白色带 alpha 的球面噪声。
- **光环**：旧的实心 `Torus` 换成带**径向分带贴图**的 `RingGeometry`（高频噪声出细密环缝、低频噪声出卡西尼缝那种大空档）。`RingGeometry` 的 UV 是平面映射，所以画布中心=环心、画布半径=环外径，直接径向画即可。

### 4. 抽成独立模块
纹理代码 370 行，堆在视图组件里不合适，抽成 **`frontend/src/utils/planetTexture.js`**（不依赖主题 store，自足）。
附带好处：可以搭一个独立的预览页跑**完全同一份代码**来做无头截图验证，不用登录、不用起后端。

### 5. 不卡首帧
九颗 512×256 合计约 0.5s。同步算会白屏卡住首帧，所以：
- 先挂 1×1 白色**占位贴图**让着色器按「有贴图」编译好（否则换图时九次重编译会在进场动画里各卡一下）
- 星球先以主题色出场，之后**一次算一颗、算好一颗换一颗**，进场动画本来就有 3.4s，换完时用户还在从虚空往里飞

## 七、中央恒星 → 黑洞（用户：「中间的点击退出球体能不能做成黑洞」）

### 定调（问过用户）
| 问题 | 用户选择 |
|---|---|
| 视觉风格 | **写实向**（《星际穿越》那种：纯黑视界 + 细亮光子环 + 赤道吸积盘 + 引力透镜弧） |
| 退出转场 | **改成被吸进去**（黑洞胀大吞掉画面 → 全黑 → 切主界面） |

### 新增 `frontend/src/utils/blackHole.js`
三个部件：
1. **事件视界**：纯黑球。`MeshBasicMaterial` 不受光照，贴上去就是全黑，把背后星空彻底吃掉。
   `side: DoubleSide` 是第一轮「放大黑洞吞掉画面」时加的（相机进到球内时若只渲染正面，背面会被剔除、画面反而透出星空）。**第六轮砍掉放大之后这条已不是必需**，保留着无害，只是别再当成必须项。
2. **光子环 + 透镜弧**：一张朝向镜头的程序化贴图。**用 billboard 而不是真做引力透镜**——真透镜要单独一整套后处理，而招牌观感（视界边缘一圈细亮环 + 吸积盘远侧的光被弯折到视界上下各成一道弧）一张贴图就能拿到，且镜头转到任何角度都成立。billboard 落在原点，中心那圈正好被视界球挡住（球面比它近），只露出外面那圈光。
3. **吸积盘**：赤道面上的环，缓慢自转（0.0022/帧）。内缘白热、向外幂律冷却，叠**角向条纹**做出湍流——拿角度当噪声坐标，绕一圈自然连续，不会在接缝处断开。

配色仍跟随用户「外观色」：视界按物理就该是黑的，主题色落在吸积盘与光子环上，**09-12 那条「中央天体联动外观色」依然成立**。

### 顺带处理的两件事
- **中心那盏点光源保留**：黑洞本身不发光，但吸积盘极亮，行星仍该被中心照亮；若顺手删灯，09-12 修好的「外圈星球沉进黑里」会当场回归。已在代码里注明原因。
- **底栏加了一句「点中央黑洞退出」**：黑洞比原来的亮恒星暗得多，而 09-12 已经把返回键拆了、这是唯一出口，不加提示容易找不到。

### 被放弃的"粒子填满屏幕"方案（记下来，别再走一遍）
第 ③~⑤ 轮做的是「粒子越聚越多、最后把整屏填成外观色」。试了很多轮，结论是**这条路本身就不划算**，最后被用户砍掉。三条踩过的结论仍然成立，将来若有人要做：
1. **靠"撒更多点"是填不满的**——点再密也是黑底上的亮点，不是一片色。要成片只能靠尺寸。
2. **必须用 alpha 混合，不能用加法混合**。加法下密度不均必然出问题：中心重叠十几倍、边缘才一两倍，中心一定累加过头、经 ACES 去饱和后烧成白色，外观色就丢了。alpha 混合的重叠是渐近的，再密也只逼近 `uColor` 本身，**数学上不可能超过它**。
3. **顶点着色器不能做透视衰减**。粒子云铺开后会有粒子掠过镜头，一带透视它们就涨到 300+ 像素、把画面烧白，覆盖率完全失控。

> 另外两个具体的坑（已修，与本方案是否保留无关）：
> - `new THREE.Color(r/255, g/255, b/255)` 是把 sRGB 数值**直接当线性色**用，渲染出来会淡一大截；要传字符串让 three 自己转，才能和片元末尾的 `colorspace_fragment` 对上。
> - 黑洞的光子环与吸积盘是加法混合，粒子海漫上来后**会一直透出来发亮**，不收掉的话画面正中会留一只"眼睛"。

### 行星「旋转吸入」的两个关键项
1. **角速度要随半径暴涨**：`spin = angle + (1/(1-fall)^1.2 - 1) * 0.85`。
   少了这一项，行星只是沿半径笔直滑向中心，看着像掉下去而不是被卷进去。
2. **缩放跟着「半径」而不是「时间」走**：行星半径和视界差不多大，
   不在贴近时收掉的话画面上是行星盖住黑洞，而不是黑洞把行星吃掉。

### 新增 `createStardust()`（`blackHole.js`）
「粒子不断变多」用**固定粒子池 + 逐渐放行**实现：池里 3200 颗，某时刻只有前 `floor(count*activeFrac)` 颗可见。每颗落到中心就重新丢回外圈，于是外圈始终有新的补进来、形成持续内流。
出场时 `activeFrac` 只涨到 **0.45**（约 1440 颗）——第六轮定的：够看出「东西被吸进去」就切走，不做填满屏幕那一套。
每颗粒子的轨迹与行星**同一套公式**（半径幂次收缩 + 角速度随半径暴涨）——用户特别强调过「粒子也是旋转吸入，只不过越来越多了」。

## 八、去掉星球外面的「球状环」（用户中途反馈）

用户：「为什么星球上有一层球状环，去掉吧」

指的是**大气辉光壳**：那是第七节之前给每颗星球套的一个 **1.32 倍半径**的球，菲涅尔亮环出现在**它自己的边缘**上，于是亮圈和星球本体之间隔着一道暗缝，看起来就像套了个玻璃泡。

## 九、一个我自己造出来的坑：dev server 缓存了「中间态」（已定位，非代码问题）

用户报错：
```
EdgeNavDock.vue:357 [Vue Router warn]: uncaught error during route navigation:
SyntaxError: Export 'makeAtmosphereMaterial' is not defined in module
```

### 排查
1. **源码是干净的**：`grep -rn makeAtmosphereMaterial src/` 无命中，`planetTexture.js` 的 export 块正确，`vite build` 通过，`dist/` 产物里也没有残留
2. **直接从用户那个 dev server（5173）把这些模块拉下来**，真相在这一步：
   ```
   curl -s localhost:5173/src/utils/planetTexture.js
   → export { ..., makeAtmosphereMaterial, getPlaceholderTexture, }   ← 还带着它
   ```
   而同一份响应的 sourcemap 里 `sourcesContent` 已经是**新版**（import 块是抽出去之后的）。
   即服务器发的是一个**中间态**：函数体已删、export 那一行还没改。

### 根因
第八节删大气壳时，我用**一条链式命令**做了三次 `sed -i` 写入同一个文件：
```
sed -i '287,313d'  &&  sed -i 's/^  makeAtmosphereMaterial,.../'  &&  sed -i 's/, atmo: [0-9.]*//g'
```
vite 的 watcher 在**第一次写入后、第二次写入前**抓了一帧并转换缓存；后续写入没让它重新转换，
于是 dev server 一直发这个自相矛盾的版本，浏览器一导航到 `/profile-card` 就炸。

### 结论与修复
**代码没问题，是 dev server 的转换缓存脏了。**

修复**不用重启进程**——给它一个干净的 change 事件让 watcher 失效缓存即可：
```
touch src/utils/planetTexture.js
```
实测 touch 之后同一个进程（PID 未变）立刻开始发正确内容。

> 中途曾判断"需要重启 dev server"（并在 5199 端口起全新服务器验证过：该符号出现 0 次、export 块正确）。
> 那步验证是对的，但**结论下早了**：脏的只是这一条缓存，touch 一下就够，没必要动用户的进程。
> 排查时注意比对 **PID 有没有变**——用户说"重启了"但 PID 没变，就是没重启，别再往代码上找。

### 教训
**对 vite 正在监听的文件不要用链式多次 `sed -i` 写入**——中间态会被 watcher 抓到并缓存。
多处修改应当：用单次写入（一次 `>` 重写整个文件），或在每次写入之间留出间隔。

## 十一、`video_admin purge` 的 storage 404 怪癖（已定位并修）

09-06 挂到现在的一条：「列表有、删除 404」（12 个孤儿音轨 ~10MB）。

**根因**：`cmd_purge` 用 `prefix: ""` 列桶，然后**直接照列出来的 name 删**。但 Supabase 的 list 对嵌套路径返回的是**「文件夹」伪条目**（`id` 与 `metadata` 均为 null），真正的对象在 `{uuid}/audio.mp3` 里——删 `{uuid}` 自然删不到东西。

**修法**：加递归 `list_all()`——`id`/`metadata` 为空即视作文件夹，带上前缀再往里列一层，只把**真实对象**的完整路径拿去删。

> ⚠️ **只改了代码，没有运行**。`purge` 会清空整个桶，这是生产数据，不该由我来跑。要清理那 12 个孤儿音轨，请你自己在确认过的环境执行。
