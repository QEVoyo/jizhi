# 2026-08-20 开发日志

## 公网部署后：新注册账号登录 401 修复

### 问题
提交新版代码到公网后，新注册的账号登录时显示 401，注册本身成功。

### 根因
Supabase Auth 默认开启「Confirm email」：`signup` 返回 200（用户创建成功，看起来注册成功），但 `email_confirmed_at` 为空；之后 `grant_type=password` 被 GoTrue 拒绝（`Email not confirmed`）→ 后端映射为 401「邮箱尚未验证」。

叠加前端 bug：`utils/request.js` 的 401 拦截器把登录接口自己的 401 也当作登录态失效处理——清空状态、跳回登录页，页面只显示 axios 通用错误 `Request failed with status code 401`，后端真实原因被吞掉。

### 修复
| 文件 | 改动 |
|---|---|
| `backend/routers/auth.py` | 注册成功后用 service role 调 `/auth/v1/admin/users/{id}` 自动 `email_confirm: true`（站点已有自己的邮箱验证码流程，Supabase Confirm email 冗余）|
| `frontend/src/utils/request.js` | 401 拦截器跳过 `/auth/login`、`/auth/register`、`/auth/wx-bind`（这些 401 是业务错误，不是登录态失效）|
| `frontend/src/stores/auth.js` | 登录/注册失败时展示后端真实 detail（如「邮箱尚未验证」「账号或密码错误」）|

### 用户需执行
- [ ] 重新部署后端 auth.py + 重启；重新 build 前端并上传 dist
- [ ] 已注册的测试账号：在 Supabase Dashboard → Authentication → Users 手动 Confirm，或直接删掉重注册
- [ ] （可选）Supabase → Authentication → Providers → Email 关闭 Confirm email
