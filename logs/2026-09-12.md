## 一、详情面板视觉重做

### 检验方式（这轮的做法值得记）
不再是"改完让用户看"。搭了**同源种子页**（写 localStorage 登录态）+ 无头 Chrome 截图**真实页面**，用真实数据渲染，逐轮看图改。共迭代 4 轮。

### 改前的毛病
| 问题 | 现状 |
|---|---|
| 图表裸浮在面板上 | 没有容器、没有边界，和背景糊在一起 |
| **没有 tooltip** | 知识/能力/认知/成长四个图根本读不出数值 |
| 网格线 `rgba(255,255,255,0.02)` | 等于不存在 |
| 知识星系 | `Math.random()` 生成的**假连线**（无语义纯噪声）+ 节点按分数放大到 50px，25 个挤成一圈互相压、标签全糊 |

### 改动
- **`dim-card` 容器**：每个维度一张渐变面 + 描边 + 内高光 + 投影，图表不再裸浮
- **KPI 摘要行**：真实数据，绿的表示好、琥珀表示弱
- **统一视觉语言**：`TIP` / `AXIS_LABEL` / `SPLIT_LINE` 三个常量，所有图共用
- **知识星系 → 极坐标星爆图**：每根射线一个知识点，长度与颜色表掌握度，取最高 18 个；假连线彻底删除
- **能力雷达**：轴数 < 3 时自动降级成横向渐变条（两根 86 分的条比一条竖线好看太多）
- **易错地图**：色相表攻克率、**明度表错题量**（只按攻克率上色时，攻克率低的账号会糊成一堵一模一样的红墙）
- **成长轨迹**：发光折线 + 渐变面积 + 均值参考线
- **学习节奏**：格子加大到 15px、青绿渐变、中文月份/星期标签

## 二、维度宇宙（主界面）重做

### 用户逐条反馈与改动
| 用户说 | 根因 | 改动 |
|---|---|---|
| 「9 个有很多没有数据」（观感） | **九个星球只用中心点光源照明（decay=1.5）**，外圈星球照不到光、近乎全黑 | 加自身颜色的 emissive 自发光 + 环境光抬亮 + 衰减放缓 → 九星全部显色 |
| 「很单薄的画像」 | 只有几个球在飘 | 加**侧栏维度清单**：九维各带真实数值与数据状态，标「9 / 9 有数据」 |
| 「星球怎么加点坐标之类的看着厉害一点」 | — | 加**极坐标星图网格**（同心刻度环 + 12 条辐射线）+ **右上角坐标面板**（R / θ / 轨道倾角 i / 离面高度 y，实时跳动） |
| 「星球都在同一平面上有点不太对」 | 轨道环全是 y=0 平面 | 每条轨道独立**倾角与升交点**（-16°~+18°），行星挂在倾斜轨道组里真沿倾角走 |
| 「中间的球体改成联动用户的外观色」 | 恒星着色器颜色写死 | 恒星核心/日冕/光晕全部取主题色轴 |
| 「点击有动画回到主界面，这样可以去掉返回键」 | — | 顶栏返回键移除，改点中央恒星退出 |
| 「进去有这个扫描维度，去掉」 | 进场时盖了一层 `load-overlay` | 删除（进场推进动画本身就是加载过程） |

### 转场动画（用户来回改了四轮）
1. 第一版：整块画布 `scale 7.5` —— 用户：「太粗糙」
2. 第二版：行星螺旋内收 —— 用户改主意：「点击中心球体，放大球体然后显示主界面」
3. 第三版：放大球体 —— 用户：「要从很远出靠近星系，从虚空」
4. **最终**：进场从虚空推进 + 出场放大中心球体

### 进场「从虚空」踩的三个坑（都值得记）
1. **相机 `far` 只到 60** —— 超过 60 单位的东西**根本不渲染**。把起点放到 z=900 时，那 800 多单位路程画面是空的（被裁掉），星系只在飞进 60 以内才「啪」地出现 → 用户感觉「太近」。改为 `far = 4000`
2. **`controls.maxDistance = 35`（写死的）** —— OrbitControls 每帧 `update()` 把相机距离夹回 35，我设 900、2600 每次都被拽回来。用户直接问「你是不是写死了什么」→ 进场期间放开到 6000，抵达后交还 35
3. **线性插值距离 → 观感是硬切** —— 视张角按 1/d 变化，从 1590 走到 21，前 80% 时间几乎没动静、最后 15% 猛扑进来。改成**对数插值**（等比例缩短距离）才是视觉匀速靠近

### 正方体虚空
星空是 `(Math.random()-0.5)*100` 铺的 **100³ 立方体**，从远处看就是方块。用户拍板：**「不是改成球状，是机位位于虚空内这样比较好」**——从里面看就没有边界。于是把星空扩到 ±1600（远层 18000 颗）+ 关闭距离衰减（`sizeAttenuation: false`，否则远处的星缩到亚像素等于消失），起点距离 1100 落在星空内部

## 三、修掉的真 bug（这轮挖出的都是硬伤）

| bug | 后果 |
|---|---|
| `.detail-enter-from` 的 `transform` 覆盖了居中用的 `translate(-50%,-50%)` | 详情面板跑到右下角被切掉 |
| 打开面板的动作只挂在 rAF 飞行循环里 | rAF 不触发（后台标签页/降帧）时**面板永远打不开** |
| 九个星球只用中心点光源照明 | 外圈星球近乎全黑 → **看着像「没数据」** |
| 相机 `far = 60` | 远处一切被裁掉，进场动画大部分是空白 |
| `controls.maxDistance = 35` 写死 | 相机永远拉不远 |
| `SpriteMaterial` 缺 `depthWrite: false` | 写深度缓冲污染后续渲染 → 整屏随机糊成灰色 |

## 四、未解决 / 存疑（如实记录）

1. **整屏随机糊成灰色**：反复出现、时有时无。已定位并修掉一个确定成因（3D 文字精灵写深度缓冲 → 已移除该精灵），但**未能根治**。**怀疑是 `--disable-gpu` + SwiftShader 软件渲染路径的问题**——用户从头到尾没报过整屏发灰，可能是我测试环境的假象。已停止在这条线上继续盲改
2. **退出转场偶发被误触发**（headless 里出现过一次白屏），触发原因不明（绑定是标准 click/mousemove）。已加自愈兜底：1.8s 内没跳转就自动撤销，不会把人锁在白屏
3. **无头截图的虚拟时间会截到 CSS 过渡中途**，验证转场类改动不可靠
