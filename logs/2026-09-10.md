## DeepSeek 模型升级至 V4.1 Flash（文本 + 识图合并成一个模型）

### 背景（用户：「将现在更新文本模型为 deepseek 新出的模型，以及图片理解模型，请你看看先」）
DeepSeek 当日发布 **V4.1 Flash**，API 名 `deepseek-flash`。代码里跑的一直是遗产名：`llm_client.py` 硬编码 `deepseek-chat`、视觉默认 `deepseek-v4-flash-vision-exp`——**两个名字都已下线**，只是被官方临时路由撑着。

### 排查（平台 key 直连官方接口实测，不靠新闻口径）
1. `GET /models` 只剩两个模型：`deepseek-flash`、`deepseek-v4-pro`（后者 09-14 12:00 起也路由到 Flash 并按 Flash 计费）
2. 旧名实测仍能调通（被路由），但属随时可断的过渡态
3. **⚠️ 最大的坑：V4.1 Flash 默认开思考模式**——裸调 `deepseek-flash` 会先在 `reasoning_content` 里推理一段再出正文
   - 流式实测首字：**0.6s → 1~13s**（闲聊 5.6s / 批改 3.1s / 解释概念 1.1s / 学情总结 3.8s / 出题 12.4s）
   - 思考计入 `max_tokens`：额度设 800 时**只思考不出正文**（等于调用失败）
   - 关闭方式实测：`extra_body={"thinking":{"type":"disabled"}}` ✅（token 73→13）、`reasoning_effort=none` ✅等效、`chat_template_kwargs` ❌无效

## 待回应：用户提出的「为什么还有非流式，全部都要是流式」

用户中途提问。已排查全部 20 处 `call_llm`（非流式）调用点，分三类：

| 类别 | 调用点 | 流式是否有意义 |
|---|---|---|
| **A 要完整 JSON** | 诊断批改 / 出题 / 评估深析 / 词条生成 / 薄弱词出题 / 真题错因 / 答卷生成计划 / 自定义计划兜底 / 生成脚本 | ❌ 无意义——必须等全文到齐才能 `json.loads`，流式只增加拼接与中断处理复杂度，体验一模一样 |
| **B 后台小任务** | 会话标题(≤15字) / 摘要标签(≤10字) / 意图分类(一个词) / 敏感词判定 | ❌ 无意义——极短输出 + 用户看不见 |
| **C 用户可见长文本** | `/chat/advice` 生成建议、学情报告 AI 总结 | ⚠️ 初判有价值，**逐条核实后不成立**（见下） |

**C 类两处核实结果**：
- 学情报告 AI 总结其实写在 `/evaluation/overview` **聚合 JSON 接口内部**（`evaluation.py:168`），报告要等它算完才能整体返回——结构上无法流式，且只要 50 字
- `/chat/advice` **前端无任何调用方**（`api/chat.js` 都不存在）→ 死端点

结论：**流式不减少总耗时，只改变「字什么时候开始出现」**。主对话（`/chat`）与三个 agents 本来就是流式；**真正值得改成流式的地方是 0 处**。用户若在意的是「等待时屏幕是死的」，正解是加载反馈（09-05 视频骨架屏 / 08-30 提交评估 LoadingSpinner 已做过），不是流式。

## 小基对话自动化改造（用户：「一定要自动判别，下拉框太掉价了」）

用户拍板：**删掉手动「呼叫对象」下拉框，改为按用户说的话自动分流**；规划/评估/生成不再「输出一大段话」，改为出可执行的卡片；输入区按键与状态跟随识别结果；上下文要压缩，不能越聊越贵。

### ① 意图判别：三级阶梯（`agents/intent_router.py` 新增）

| 级 | 手段 | 成本/延迟 | 覆盖 |
|---|---|---|---|
| ① 规则层 | 明确指令词命中即分流（strong 任意长度 / soft 仅短句） | **0 元 / 0ms** | 「出题」「做个学习计划」「分析一下我的」这类标准说法 |
| ② 关键词门 | 不含任何「像派活」的词 → 判闲聊；**带疑问词也判闲聊**（那是在问，不是在派活） | **0 元 / 0ms** | 绝大部分闲聊、知识问答、情感倾诉 |
| ③ 模型层 | 仅「像派活但规则没抓住」时调一次 qwen-flash | ~0.004 分、~0.4s | 「帮我把错题练一下」这类换说法 |

- 设计原则：**默认闲聊**——判成闲聊的代价是用户再说一句，误判成派活会打断用户
- 实测 23 条真实消息：**只有 2 条**落到第 ③ 层；「这道题怎么做」被疑问词正确挡在门外

### ② 接入：省一次往返（`community/xiaoji.py`）

- 新增 `POST /community/xiaoji/route`（`deep=false` 只跑 ①②，供输入框实时预判）
- `chat-stream` **内部判别**：闲聊 → 原样流式；派活 → **直接返回 JSON 路由指令**（不打字，由前端出卡片）——不额外增加一次网络往返
- `force_chat`：陪伴 chips（「背个单词」「求安慰」）跳过判别固定走队长
- 原 `agent_key` 手动通道移除；`AGENT_PERSONAS` 与 `_build_agent_grounding` 暂无调用方，**保留并注释**（是任务 8 个性化计划要复用的输入）
