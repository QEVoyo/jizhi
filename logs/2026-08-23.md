## API 模型中心：预览形式改版

### 背景
页面原为「预览画廊」但预览是静态文字块（`问：…\n答：…` 一坨），效果差。用户确认保留预览形式、只改进预览效果；同时确认当前所有 AI 调用用平台官方 Key，**后期规划改为用户自带 Key 优先、平台兜底**。

### 预览形式（`frontend/src/views/ApiCenter.vue`）

| 类型 | 卡片 | 表现 |
|---|---|---|
| 对话气泡 | DeepSeek Chat / 智谱 GLM | 「我」提问气泡 + 小基头像回答气泡；展开卡片时打字机逐字重播（2 字/20ms），打字中头像切换 `xiaoji_speaking.png` + 闪烁光标 ▌；收起即停、再展开重播 |
| 识图 | DeepSeek Vision | 左侧「示例题目截图」纸质 mockup（米色纸面 + 衬线体 + 斜置 1.2° 仿拍照）+ 右侧小基解析气泡 |
| 语音 | 讯飞星火 | 输入文案 + 播放按钮 → 真实调 `POST /xiaoji/tts` 讯飞合成，base64 mp3 本地播放；取回后缓存复用（重复点击不再消耗）；播放中均衡器动画 + 实际时长（加载后显示真实时长） |
| 状态 | 豆包 | 主链路 / 待命备用两行状态 |
| 视频 | 腾讯云数字人 | 16:9 渐变占位帧 + 播放按钮，点击提示「占位中，上线后启用」 |

- 模型数据从 `previewLabel/preview` 纯文本改为结构化 `preview: { type, label, question, answer, output, lines, text }`，按 type 渲染
- 打字动画：`typing` 状态 + 定时器，展开/收起联动，卸载时清理；`onBeforeUnmount` 停所有定时器、暂停音频、revokeObjectURL
- TTS 复用 `utils/request`（`/xiaoji/tts` 无鉴权，直接可用）；失败 ElMessage 报错不影响页面
- 副标题改「点击卡片展开详情，可重播演示」；构建验证通过（vite build 1.5s）

### 后期规划（用户自带 Key，未实施）
- Supabase `user_api_keys` 表 + RLS + 掩码回显 + 加密存储；调用优先级「用户个人 Key > 平台 Key」

## 智能体中心：后端全量落地（08-22 只有硬编码预览，今日接真实数据）

### 数据设计（`agent_center_design.md` + `backend/sql/agent_center_tables.sql`）

- **原则：能用现有表就不建新表**。调用计数统一走 `user_actions`（action_type + metadata.touchpoint），效果指标统一走业务表，只新建 2 张表 + 2 个补列：
  - `agent_prefs` — 智能体参数持久化（user_id + agent_key + param_key 唯一，param_value JSONB，auto_managed 自动托管开关）
  - `agent_tuning_log` — 磨合记录（old/new value + reason + source: auto/manual），趋势图 markLine 数据源
  - 补列：`xiaoji_messages.kind`（chat/vision/evaluate 触点区分）、`subject_plans.source`（diagnosis/exam_paper 计划来源）
- **19 个触点**全清单（对话 6 / 规划 4 / 生成 4 / 评估 4 / 小基 5），其中 12 个现成可计数、4 个补埋点、2 个词条触点随词条功能走，0 个为计数建新表

### 后端聚合路由（`backend/routers/agent_center.py`，挂载 `/agent-center`）

| 端点 | 说明 |
|---|---|
| `GET /agent-center/overview?user_id=&days=` | 总览：KPI 六格（总调用/活跃智能体/计划完成率/生成题量/批改题量/词条抓取）+ 协作闭环 5 步 + 小基陪伴线 + 协同增益 5 对（跨表对照：陪伴日 vs 非陪伴日等）+ 路由转化 + 动态结论文案 |
| `GET /agent-center/agents/{key}` | 单智能体详情：30 天趋势序列 + 4 统计格 + 触点计数表 + 2 个特点面板（各 agent 不同） |

- 性能：15 张表数据**单连接 + asyncio.gather 并发拉取**（否则串行 14 个请求 10s+），跨表联合全在 Python 侧完成；任何查询失败优雅降级返回 []
- 数据原则落地：每个数字要么解释学习效果、要么导向动作

### 磨合规则引擎（`backend/agents/tuning.py` 🆕）

6 条规则（与详情页参数卡「磨合规则」文案一一对应）：

| 规则 | 触发条件 | 动作 |
|---|---|---|
| 规划·每日任务量 | 完成率 <50% / >85% | -2（下限 1）/ +1（上限 10） |
| 规划·阶段节奏 | 完成率 <40% / 近 14 天 >80% | 降一档 / 升一档（舒缓→适中→紧凑） |
| 生成·出题难度 | 题集收录率 <60% / >85% | -2 / +1 |
| 生成·错题针对性 | 错题本 ≥10 题且未开启 | 开启 |
| 评估·错因颗粒度 | 重做正确率 <70% | 加细到知识点级别 |
| 小基·关心频率 | 连续 3 天没学习 | +1 档（无学习记录的新用户不打扰） |

- 保护机制：用户关了「自动托管」的参数不碰；同一参数自动调整有 7-14 天冷却期；单条规则失败不影响其余
- 触发：详情页「立即评估」按钮（POST /tuning/run）+ **后台每日任务**（main.py lifespan 启动 asyncio 循环，24h 一次，近 14 天活跃用户逐个评估，用户间限速 1s）

## 全局搜索：增删改查（同日第三轮）

用户要求搜索也具备增删改查，选定两层：**历史记录管理** + **自定义搜索项**。

### 历史记录管理（localStorage，零后端）
- 最近访问：每条 hover 出 ✕ 单删 + 组头「清空」一键清
- 搜索历史：chip 内 ✕ 单删 + 组头「清空」
- store 新增 `removeRecent/clearRecent/removeSearch/clearSearch`

### 自定义搜索项（用户增删改查）
- **增**：面板空态「＋ 添加」（组头/页脚两处入口）→ 内联表单：名称（必填）+ 别名（可选，逗号分隔）+ 目标路径（必填，/ 开头校验）
- **查**：作为「自定义」组参与模糊匹配（名称 + 别名），位置在页面组之后
- **改**：条目 hover 出 ✎ → 表单预填 → 保存即生效
- **删**：条目 hover 出 🗑 → 删除
- 存储：localStorage **按用户隔离**（`gs_custom_entries_{uid}`）

### 验证（CDP 端到端 10 项全过，零控制台错误）
增 → 别名命中 → 编辑预填 → 重命名生效 → 删除回空态 → 历史自动记录 → 历史单删 → 历史清空 → 最近访问单删；vite build 通过。测试中发现面板内存在两个「清空」按钮（最近访问/搜索历史各组一个），属设计使然，测试选择器按组定位。

### 交互重构：自定义项从手填表单改为点选收录（同日第四轮）
用户反馈「自定义就是给出全部可快捷进入的页面，然后点击自定义添加才对，而不是自己添加」——废弃自由表单，改为**快捷入口选择器**：

- 「＋ 添加」→ 选择器模式：分组列出全部可快捷进入的页面（页面 / 考纲 17 / 真题 12 / 智能体 5，不含词条），上方搜索框实时筛选
- 每条右侧「＋ 添加」按钮点选收录，收录后变「✓ 已添加」，再点一次移除（钉选式 toggle）
- 名称/路径/别名全部取自索引，**用户零手填**
- 重命名保留为「改」：✎ 内联输入，旧名自动保留进别名（改名后仍可被旧名搜到）
- 选择器内 Esc 先退出选择器（再按才关面板），Enter/↑↓ 在选择器模式下不触发跳转

### 验证（CDP 端到端 12 项全过，零控制台错误）
