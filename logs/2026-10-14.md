## 一、两个文件是什么

一对**配套**材料：《公路建设管理系统V1.0》的说明书 + 代码1-60页。

「配套」不是猜的 —— 说明书 §5.2 合同管理列的字段（合同编号 / 合同类型 / 合同金额 /
合同签订日期 / 合同起止日期 / 甲方名称 / 乙方名称），正是代码里 `contractMForm` 那一组。

| 文件 | 规模 | 结构 |
|---|---|---|
| 说明书 | 243 行文字 + **50 张截图**（5.7 MB） | 封面 → 系统概述 → 登录 → 管理中心（4 张统计图的文字说明）→ 五个业务模块 |
| 代码 1-60 页 | 2946 段，**0 张图** | 无手动分页符，靠行数自然分页 |

说明书的写法**高度模板化**：每个功能都是「导航到X → 新增 → 编辑 → 删除 → 批量删除」一套句式，
少数几个多一段「导出成 pdf / 类型统计」。全篇就是这个模子换名词。

## 二、🎯 从模板量出来的排版参数（可直接复刻）

**代码文档** —— 这份的参数最有用，因为我们那份要长得一样：

| 项 | 值 |
|---|---|
| 页面 | A4（11907 × 16840 twips） |
| 页边距 | 上 2.12 / 下 2.20 / 左右 2.82 cm |
| 字体字号 | 宋体 **9pt**（小五） |
| 行距 | **固定值 13.2 pt**（`exact 264`） |
| 首行缩进 | 0.7 cm |
| **行号** | **有**（`w:lnNumType countBy="1"`） |
| 分页 | 无手动分页符 |

**说明书**：A4，四周 1.27 cm 的窄边距（比代码文档窄得多，为的是把截图放大）。

### ⚠️ 60 页这个数，我算出来的和文件名对不上

按版面几何算：正文高 `(16840 − 1202 − 1247) / 20 = 719.6pt`，除以行距 13.2pt = **54.5 行/页**，
2946 行 ÷ 54 ≈ **55 页** —— 比文件名里的「60 页」少。

**没在 Word 里实际渲染核对过**（本机没法可靠地跑 Word 排版）。差别可能来自页眉占位、
孤行控制、或段前间距 `before=20`。**动手前先拿 Word 开一次数真实页数**，
别拿我这个估算当准数。要凑 60 页的话，按 54 行/页估大约需要 **3200+ 行**。

## 三、⚠️ 代码模板是拼凑灌水的 —— 只能当**排版**范本

**这是今天最值钱的一条发现。** 那份「代码1-60页」的示例内容不是任何真实项目的代码：

大约每隔一行就混进一条**完全无关项目**的代码：

| 出处 | 混进来的行 |
|---|---|
| labelImg | `from labelImg import get_main_app`、`self.actions.onShapesPresent` |
| py2app | `strip_dsym`、`LC_DYLD_ENVIRONMENT`、`ev.accept()`、`macholib` |
| py2exe | `Originally (loosely) based on code in py2exe's build_exe.py by Thomas Heller.` |
| mesh_tensorflow | `mtf.convert_to_shape(...)`、`gpt2.model(mtf_features, ...)`、`logits, loss, loss_batch` |
| Sphinx | `extensions = ['djangodocs', 'sphinxcontrib.blockdiag']` |
| PaddleOCR | `options["language_type"] = "CHN_ENG"` |
| graphviz | `dot.save_img(file_name='graph', file_type='gif')` |
| openai-python | `distribution. Lower temperature results in less random completions.` |
| Django / ftfy / tokenizers | `TIME_ZONE = 'Asia/Shanghai'`、`ftfy.fix_text(...)`、`from tokenizers import Tokenizer` |

**这些行语法上不可能共存于同一个文件** —— 同一份源码里既 `from labelImg import get_main_app`
又 `class contractMForm(FlaskForm)`。

属于该示例项目的那一半，则带着明显的**代码生成器**痕迹：`self.table.contractM(row, column)`、
`id_constructiRbi = self.table.constructiRbi(row, 0)` —— 方法名被当成占位符整批替换过，
`contractM` / `constructiRbi` 是生成产物，不是人起的名字。

> **结论：模板的版式照抄，内容一个字都不抄。** 我们从自己仓库里取真代码。

## 教训

**① 「模板」有两层意思，拿到先分清。**
「照模板来」可能是**版式**范本，也可能是**内容**范本 —— 这次是前者，而且必须只是前者
（模板的内容是灌水的）。不问清就默认「照着写」，会把拼凑的垃圾一起抄进来。

**② 我被邻件误导了。**
工作目录里躺着一份 `2026AIC-算法创新赛-作品方案模板示例.doc`，我据此把这两个新文件
猜成了竞赛材料。实际是**软著**，两条完全不相干的线。**目录里有什么 ≠ 这次要做什么。**

**③ Windows 上 Python 打印中文会乱码，别当成文件损坏。**
本机 `sys.stdout` 编码是 GBK，`print('#合同编号')` 出来是 `#��ͬ���`。
我一度怀疑 docx 里的中文坏了，差点报一个**根本不存在的故障**。
绕法：`sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')`，
或落成文件再用 Read 工具读。
**教训的形状和 10-11 那次乌龙一样：测量工具自己出错时，会造出一个看起来极严重的假象。**
